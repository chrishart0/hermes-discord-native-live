# Repository workflow

For agent work requested by the repository owner, use `master` directly.

- Commit and push changes to `master` after validation. Do not create feature branches or pull requests unless explicitly requested.
- Keep `master` as the default branch; do not introduce or switch to `main`.
- Read the latest remote state before editing. Preserve existing changes and do not force-push or rewrite published history.
- Keep changes focused and readable. Report which checks actually ran and distinguish automated tests from live Discord/GPT-Live testing.
